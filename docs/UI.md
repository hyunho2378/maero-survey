# 마에로와 삐삐로 UI

기준일: 2026-11-02

## 1. 제품과 변경 범위

- 플랫폼은 B형 반응형 웹이다.
- 지원 목표는 320px부터 3840px까지이다.
- 춘천마임축제가 주인공이며 마에로와 삐삐로는 길잡이다.
- 캐릭터 팬이 만든 스티커북과 작은 마임 극장을 시각적 방향으로 삼는다.
- 설문은 중앙 정렬된 단일 열을 유지한다.
- 질문 순서, 선택 방식, 검증, 추적, 저장, 제출 잠금과 재시도 계약을 바꾸지 않는다.
- 기존 화면 문구는 보존한다.
- 진행 상태를 설명하는 짧은 문구만 추가한다.
- 그림이 없어도 제목, 설명, 탐색과 설문은 사용할 수 있어야 한다.

## 2. 시각 원칙

1. 크림 바탕과 흰 카드가 화면의 대부분을 차지한다.
2. 키치한 인상은 손글씨 제목, 흰 외곽의 스티커, 기울어진 종이와 물결에서 만든다.
3. 질문과 선택지의 배치는 정돈된 상태를 유지한다.
4. 일반 제목과 본문을 굵게 만들어 위계를 만들지 않는다.
5. 캐릭터를 과도하게 확대하지 않는다.
6. 질문 본문 위에는 장식을 겹치지 않는다.
7. 카드, 버튼과 입력칸에는 장식용 테두리를 사용하지 않는다.
8. 키보드 포커스의 outline은 접근성 표시이므로 예외로 유지한다.
9. SVG 내부의 흰 외곽선과 그림의 선은 UI 테두리 금지 대상이 아니다.
10. 사진, 영상과 기존 외부 콘텐츠의 색은 브랜드 면적 산정과 별도로 검수한다.

## 4. 직접 계산한 색 대비

계산은 불투명한 단색 전경과 배경을 기준으로 한다.
표시 값은 소수 둘째 자리로 반올림했으며 합격 판단은 반올림 전 값으로 했다.

각 sRGB 채널을 255로 나눈 값을 $c$라고 할 때:

$$
c_{\mathrm{linear}} =
\begin{cases}
c / 12.92, & c \le 0.04045 \\
((c + 0.055) / 1.055)^{2.4}, & c > 0.04045
\end{cases}
$$

$$
L = 0.2126R_{\mathrm{linear}}
  + 0.7152G_{\mathrm{linear}}
  + 0.0722B_{\mathrm{linear}}
$$

$$
CR = \frac{L_{\mathrm{lighter}} + 0.05}
           {L_{\mathrm{darker}} + 0.05}
$$

- 빨강 위 작은 흰 글자는 사용하지 않는다.

- 노랑, 빨강, 분홍과 하늘색 위에는 남색 글자를 사용한다.
- 이미지에 포함된 글자, 실제 합성 결과와 포커스의 인접 색은 별도 브라우저 검수가 필요하다.

## 5. 타이포그래피

제목 서체는 Gaegu 400을 선택한다.
본문과 질문은 Pretendard를 사용한다.
이 선택은 이번 디자인 판단이며 두 서체의 실사용 가독성 비교 검증 결과는 아니다.

| 역할 | 서체 | 굵기 | 크기 | 행간 | 자간 |
|---|---|---:|---|---:|---|
| 페이지 제목 | Gaegu | 400 | 40px부터 56px | 1.18 | -0.025em |
| 섹션 제목 | Gaegu | 400 | 28px부터 36px | 1.3 | -0.025em |
| 질문 | Pretendard | 500 | 20px부터 24px | 1.5 | 0 |
| 본문 | Pretendard | 400 | 16px부터 20px | 1.75 | 0 |
| 선택지와 버튼 | Pretendard | 500 | 16px부터 20px | 1.5 | 0 |
| 선택된 선택지 | Pretendard | 600 | 선택지와 같음 | 1.5 | 0 |
| 보조 설명 | Pretendard | 400 | 13px부터 16px | 1.75 | 0.015em |
| 스티커 문구 | Gaegu | 400 | 섹션 제목 크기 | 1.3 | 0 |

- 600은 선택된 선택지에만 사용한다.
- strong과 b는 기본적으로 500이다.
- font-synthesis: none을 적용한다.
- 글꼴의 @font-face 선언에 들어가는 family와 weight는 CSS 문법상 리터럴을 사용하는 예외다.
- 외부 글꼴을 불러오지 못하면 시스템 글꼴로 표시한다.
- 현재 코드는 기존 Pretendard CDN을 유지하고 Gaegu 400만 요청한다.
- 글꼴을 프로젝트에 직접 배포할 때는 원본 저작권 고지와 라이선스도 함께 관리한다.

## 6. 한국어 줄바꿈

- 전역 word-break는 keep-all이다.
- 전역 overflow-wrap: anywhere는 사용하지 않는다.
- 주소, 이메일과 코드에만 anywhere를 허용한다.
- 제목은 text-wrap: balance를 사용한다.
- 본문은 text-wrap: pretty를 사용한다.
- 고정 핵심 문구의 절 경계는 tokens.js의 uiCopy에 |로 기록한다.
- Phrase는 구분자를 출력하지 않고 절 사이에 공백을 넣는다.
- 절은 inline-block으로 렌더한다.
- 긴 절은 컨테이너를 넘지 않도록 절 내부의 어절 경계에서도 줄바꿈할 수 있다.
- 외부 질문 데이터의 문장은 수정하지 않는다.
- 외부 질문 데이터와 개인정보 컴포넌트의 절 경계는 실제 원문과 렌더를 보고 추가 검수한다.
- K1부터 K5의 통과는 실제 줄 상자 측정 후에만 선언한다.

### 유동 크기

- 페이지 좌우 여백은 clamp(0.75rem, 2.4vw, 3rem)이다.
- 카드 좌우 여백은 clamp(1rem, 0.6rem + 1.8vw, 2.5rem)이다.
- 카드 상하 여백은 clamp(1.5rem, 1rem + 1.2vw, 2.5rem)이다.
- 섹션 여백은 clamp(3.5rem, 7vw, 8rem)이다.
- 전체 콘텐츠 최대 폭은 clamp(70rem, 78vw, 112rem)이다.
- 설문 최대 폭은 clamp(40rem, 31rem + 10vw, 55rem)이다.
- 기본 루트 글자 크기가 16px일 때 설문은 일반 화면에서 약 640px이며 4K에서는 최대 880px이다.
- 설문이 커질 때 본문, 질문과 보조 글자도 토큰에 따라 함께 커진다.
- 루트 글자 크기를 고정하지 않아 사용자 글자 크기 설정을 존중한다.
- 긴 설명의 읽기 폭은 44rem 이내로 제한한다.

### 조작 크기

- 기본 터치 영역은 최소 2.75rem이다.
- 선택지 높이는 최소 3.5rem이다.
- 척도 선택지는 최소 4.5rem 높이이다.
- 제출 버튼 높이는 최소 3.75rem이다.
- 선택 표시 내부 도형은 1.25rem이다.
- 스티커는 1rem, 2rem, 4rem 세 단계이다.

## 8. 형태와 그림자

- 카드 반경은 1.5rem이다.
- 버튼, 선택지와 입력칸 반경은 999px이다.
- 그림자는 0 8px 24px rgba(20, 23, 61, 0.10) 한 종류이다.
- 스티커의 drop-shadow도 같은 그림자 토큰을 사용한다.
- SVG 좌표, 비율, viewBox와 도형의 선 두께는 그림의 기하 값이다.
- CSS의 0, 100퍼센트, 그리드 비율과 구조용 반복 횟수도 기하 값이다.
- 기하 값 외에 색, 간격, 폰트, 그림자와 모션을 컴포넌트에서 새로 만들지 않는다.

## 9. 장식

라이브러리에는 다음 16종을 제공한다.

1. 마에로 눈 모티프
2. 파란 베레모
3. 빨간 베레모
4. 줄무늬 조각
5. 장미
6. 꽃잎
7. 물방울
8. 불꽃
9. 병아리 얼굴 모티프
10. 병아리 발자국
11. 다섯 갈래 별
12. 네 갈래 반짝임
13. 말풍선
14. 무대 막
15. 장갑
16. 선택 도장

- 실제 화면에는 라이브러리 전체를 한꺼번에 배치하지 않는다.
- 이번 화면에서 사용하는 장식 유형은 별, 장미, 발자국, 도장과 물결이다.
- 질문 번호와 선택 도장은 정보를 전달하는 전용 공간 안에 둔다.
- 질문 문장과 선택지 문장 위에 장식을 겹치지 않는다.
- 일반 장식은 머리 영역과 카드 사이에만 둔다.
- 카드 사이 장식은 세 번째와 여섯 번째 질문 다음에 둔다.
- 모든 장식 SVG는 aria-hidden이며 포커스를 받지 않는다.
- 기울기는 0도, -8도와 8도만 사용한다.
- 장식의 무한 반복 애니메이션은 없다.
- 실제 뷰포트의 장식 종류와 중첩 여부는 렌더 후 다시 확인한다.

## 10. 컴포넌트 상태 계약

### 버튼

- 기본은 단색 면과 알약형이다.
- hover가 가능한 장치에서만 위로 0.25rem 이동한다.
- 누름은 scale(0.97)이다.
- focus-visible에는 명확한 outline이 있다.
- disabled는 클릭 불가 커서와 다른 면으로 구분한다.
- disabled에서도 글자 대비를 불필요하게 낮추지 않는다.
- 제출 버튼은 빨강이며 기존 제출 문구를 유지한다.
- 전송 중에는 버튼을 비활성화하고 aria-busy를 표시한다.

### 선택지

- 기본은 크림 면과 파란 선택 표시이다.
- 선택되면 파란 면, 흰 글자, 굵기 600과 흰 도장을 표시한다.
- 색만으로 선택 여부를 전달하지 않는다.
- radio와 checkbox의 네이티브 입력 의미와 키보드 동작은 유지한다.
- 커스텀 모양만 적용한다.
- 입력 포커스는 선택지 전체의 outline으로 표시한다.
- 척도 선택지도 같은 선택 상태를 사용한다.
- 선택 도장 공간을 항상 확보해 선택할 때 문장이 밀리지 않도록 한다.

### 오류

- 기본 시각 효과는 첫 번째 오류 질문의 짧은 좌우 흔들림이다.
- 오류 문구, role=alert, aria-invalid와 aria-describedby는 보존한다.
- 기본 오류 설명은 화면에서만 숨기며 접근성 트리에서는 제거하지 않는다.
- 움직임 줄이기에서는 흔들림 대신 기존 오류 문구를 정적으로 표시한다.
- 이메일 형식 오류는 기존 설명을 남색으로 표시한다.
- 전송 실패와 재시도 안내는 숨기지 않는다.
- 검증 함수와 첫 오류 포커스 이동 함수는 변경하지 않는다.
- 같은 오류 상태로 다시 제출했을 때 CSS 애니메이션이 재시작하는지는 별도 검수 대상이다.

### 진행 표시

- 기존 answers에서 응답 여부만 읽어 계산한다.
- 설문 답변, 타임스탬프, 추적과 제출 payload에 값을 추가하지 않는다.
- 이메일과 이메일 동의는 진행 개수에서 제외한다.
- 진행 표시는 답한 문항 수이며 검증 통과율이나 영상 시청률이 아니다.
- 각 발자국은 해당 문항에 응답했는지 나타낸다.
- 진행 표시 자체는 클릭할 수 없다.
- progressbar의 접근 가능한 이름과 현재 값을 제공한다.

### 이미지

- Character의 기존 3D, 2D, 텍스트 대체 순서를 유지한다.
- 첫 화면은 3D 우선 슬롯을 사용한다.
- 이야기 카드의 기존 .story-art와 .character 배치를 지원한다.
- 이야기 카드 컴포넌트 자체는 이번 첨부에 없으므로 호출 props 변경을 추정해서 추가하지 않는다.
- 장식 동시 움직임을 줄이기 위해 이야기, 소개와 결과 영역의 캐릭터 기울임은 CSS로 정지한다.
- 첫 화면 캐릭터의 기존 기울임은 유지한다.

## 11. 모션

| 역할 | 토큰 | 값 |
|---|---|---|
| 짧은 반응 | --duration-fast | 200ms |
| 오류 흔들림 | --duration-medium | 400ms |
| 이징 | --ease-out | cubic-bezier(0.2, 0.8, 0.2, 1) |
| 누름 | --press-scale | 0.97 |
| hover 이동 | --hover-lift | -0.25rem |
| 오류 이동 | --shake-distance | 0.25rem |

- 새 애니메이션은 transform과 opacity만 사용한다.
- 색, 그림자, 크기와 위치 속성을 transition하지 않는다.
- 장식의 자동 반복 움직임은 사용하지 않는다.
- prefers-reduced-motion에서는 애니메이션과 transition을 끈다.
- prefers-reduced-transparency에서는 그림자를 제거한다.
- prefers-contrast: more에서는 보조 글자를 진하게 하고 포커스를 강화한다.
- 지원하지 않는 환경에서도 기본 화면은 불투명한 면으로 읽을 수 있어야 한다.

## 12. 반응형과 레이어

- 64rem 이하에서 갤러리를 한 열로 바꾼다.
- 48rem 이하에서 헤더, 첫 화면, 주요 카드와 푸터를 한 열 구조로 바꾼다.
- 36rem 이하에서 이야기 카드와 결과 캐릭터를 한 열로 바꾼다.
- 미디어 쿼리 값은 CSS 사용자 정의 속성을 사용할 수 없는 구조 조건이므로 리터럴 예외이다.
- 페이지 전체에 overflow-x: hidden을 적용해서 결함을 숨기지 않는다.
- 표만 자체 가로 스크롤 컨테이너를 사용할 수 있다.
- sticky 헤더의 레이어는 30이다.
- 건너뛰기 링크의 레이어는 100이다.
- 앵커 이동의 상단 여유는 12rem이다.
- 단순 장식 레이어는 각 영역의 isolation 안에서 관리한다.
