# 몸짓을 만나러 가요

한림대 학생 창업팀 버터와플의 춘천마임축제 탐색 설문 프로젝트다.

React 18.3.1과 Vite 7 계열을 사용한다.

춘천마임축제 공식 운영 사이트가 아니다.

## 원본 확인 범위

첨부 ZIP의 실제 파일에 접근하지 못했다.

다음 문서의 원문은 확인하지 못했다.

- fullstack-product-setup/SKILL.md
- references/UI.md
- references/korean_linebreak.md

assets-img의 PNG도 직접 열어 확인하지 못했다.

따라서 원본 스킬 준수와 캐릭터 외형 일치를 검증했다고 주장하지 않는다.

이 프로젝트는 사용자 메시지에 명시된 요구사항으로 작성했다.

## 실행

Node.js 22.12 이상을 사용한다.

프로젝트 루트에서 npm install을 실행한다.

npm run dev로 개발 서버를 실행한다.

npm test로 포함된 단위 테스트를 실행한다.

npm run build로 dist를 만든다.

npm run preview로 빌드 결과를 확인한다.

의존성을 설치한 뒤 생성되는 package-lock.json을 저장소에 커밋하고,
운영 CI는 검증된 잠금 파일을 기준으로 npm ci로 전환하는 것을 권장한다.

이 응답 작성 환경에서는 설치, 테스트, 빌드를 실행하지 않았다.

## 3D 이미지 규칙

3D 파일은 모두 public/img 아래에 넣는다.

이 프로젝트는 AI 이미지를 생성하지 않는다.

추후 생성한 파일을 아래 이름으로 넣으면 코드 변경 없이 사용한다.

| 파일 | 내용 | 권장 형태 |
| --- | --- | --- |
| 3d_maero_basic.png | 기본 마에로 | 투명 배경, 정사각형 |
| 3d_maero_blue.png | 물의 마에로 | 투명 배경, 정사각형 |
| 3d_maero_red.png | 불의 마에로 | 투명 배경, 정사각형 |
| 3d_pipiro.png | 삐삐로 | 투명 배경, 정사각형 |
| 3d_scene_arrival.png | 처음 만나는 장면 배경 | 캐릭터와 글자 없는 배경 |
| 3d_scene_water.png | 물의 장면 배경 | 캐릭터와 글자 없는 배경 |
| 3d_scene_fire.png | 불의 장면 배경 | 캐릭터와 글자 없는 배경 |

캐릭터는 3D 파일을 먼저 읽는다.

img onError가 발생하면 2D 파일을 읽는다.

2D도 없으면 깨진 이미지 대신 이름과 준비 안내를 보여 준다.

배경 이미지는 선택 자료이므로 없으면 기본 면만 표시한다.

3D 파일의 기울임은 마우스로 작동한다.

기기 기울임은 사용자가 버튼을 누른 뒤 활성화한다.

기기 권한을 거절해도 다른 기능을 막지 않는다.

prefers-reduced-motion 설정에서는 기울임과 부드러운 스크롤을 끈다.

## 축제 사진 넣기

public/photos에 사용 권한을 확인한 사진을 넣는다.

src/data/festival.js의 photos 배열을 수정한다.

각 항목에는 id, file, description, source를 사용한다.

file 예시는 photos/water-01.jpg이다.

source에는 실제 사진의 출처 페이지 HTTPS 주소를 넣는다.

사진 파일과 출처가 모두 있어야 실제 사진을 표시한다.

둘 중 하나가 없으면 준비 안내를 표시한다.

출처 표기만으로 사용 권한이 확보되는 것은 아니다.

이 프로젝트에 타 사이트 사진을 복사하거나 포함하지 않았다.

## 환경 변수

.env.example을 .env.local로 복사한다.

| 이름 | 설명 |
| --- | --- |
| VITE_ENDPOINT | Apps Script의 /exec 실행 URL |
| VITE_PRIVACY_CONTACT | 팀이 실제 관리하는 공개 문의 이메일 |

VITE_ENDPOINT가 없으면 localStorage 모드다.

VITE_PRIVACY_CONTACT가 없거나 이메일 형식이 아니면
소식 받을 이메일 입력을 비활성화한다.

VITE 환경 변수는 브라우저 번들에서 확인할 수 있다.

관리자 토큰이나 다른 비밀값을 VITE 변수에 넣지 않는다.

## 로컬 모드

응답은 현재 브라우저의 localStorage에 저장한다.

다른 브라우저나 기기의 응답과 합쳐지지 않는다.

이메일을 입력했다면 이메일도 현재 브라우저에만 저장한다.

팀으로 전송되거나 소식 발송 목록에 등록되는 것은 아니다.

공용 기기에서는 실제 이메일을 넣어 테스트하지 않는 편이 안전하다.

만료된 로컬 데이터는 다음 저장 또는 관리자 조회 시 정리한다.

브라우저를 다시 열지 않으면 localStorage에서 즉시 물리적으로
삭제되는 것은 아니다.

## Apps Script 설정

Google 스프레드시트를 하나 만든다.

Apps Script 프로젝트에 server/apps-script.gs 내용을 넣는다.

프로젝트 설정의 스크립트 속성에 다음 값을 추가한다.

| 속성 | 값 |
| --- | --- |
| SPREADSHEET_ID | 데이터를 저장할 스프레드시트 ID |
| ADMIN_TOKEN | 충분히 무작위인 32자 이상의 비밀 토큰 |
| PRIVACY_CONTACT | 실제 운영 문의 이메일 |
| NEWSLETTER_ENABLED | 이메일 수집을 운영할 때 true |

ADMIN_TOKEN은 브라우저 코드와 저장소에 기록하지 않는다.

PRIVACY_CONTACT는 프런트의 VITE_PRIVACY_CONTACT와 같게 운영한다.

선택 이메일 수집을 켜려면 NEWSLETTER_ENABLED를 true로 설정한다.

수집을 끄려면 서버 속성을 false로 설정하고 프런트의
VITE_PRIVACY_CONTACT도 비운 뒤 다시 빌드한다.

setupProject를 편집기에서 한 번 실행하고 권한을 승인한다.

이 함수는 Responses 시트와 하루 단위 만료 정리 트리거를 만든다.

동일한 정리 함수의 기존 트리거만 대체한다.

그다음 웹앱으로 배포한다.

익명 참여를 받으려면 운영 계정의 정책이 허용하는 범위에서
로그인하지 않은 사용자도 실행할 수 있게 공개해야 한다.

실행 주체는 배포 소유자로 설정한다.

배포 화면에서 제공되는 /exec URL을 VITE_ENDPOINT에 넣는다.

코드 수정 후에는 웹앱 배포 버전도 갱신한다.

## 전송과 성공 확인

요청 본문은 JSON 문자열이다.

Content-Type은 text/plain;charset=UTF-8을 사용한다.

임의의 커스텀 헤더를 추가하지 않는다.

서버는 e.postData.contents를 JSON으로 해석한다.

브라우저는 응답 JSON의 ok와 응답 ID를 확인한다.

no-cors의 불투명 응답을 성공으로 간주하지 않는다.

네트워크 오류 때 서버가 이미 저장했을 가능성이 있으므로
같은 ID와 같은 본문으로 재시도한다.

서버는 스크립트 잠금과 ID 검색으로 중복 행을 막는다.

실패 시 로컬 저장으로 몰래 전환하지 않는다.

재시도할 때는 기존 응답을 수정하지 못하게 잠근다.

실패한 응답은 현재 페이지 메모리에 남는다.

새로고침 후의 복구는 구현하지 않았다.

실제 GitHub Pages 도메인과 Apps Script 공개 배포 조합에서
CORS, 리다이렉트, 권한, 성공 응답 읽기를 반드시 확인한다.

계정 정책이나 브라우저 조건으로 읽기가 막히면 성공 처리하지 않는다.

## 관리자

사이트 주소에 ?admin=1을 붙인다.

로컬 모드는 현재 브라우저의 데이터만 조회한다.

서버 모드는 관리자 토큰을 입력해야 목록을 반환한다.

?admin=1 자체는 인증 수단이 아니다.

서버가 토큰을 검증한다.

토큰은 POST 본문으로 보내며 URL이나 localStorage에 저장하지 않는다.

응답 표와 처음 평균, 지금 평균을 확인할 수 있다.

CSV는 불러온 응답의 전체 필드를 포함한다.

이메일과 동의 정보도 포함하므로 파일 접근 권한을 관리해야 한다.

이 구현은 소규모 파일럿용이다.

공개 제출 주소는 자동 제출이나 조작을 완전히 방지하지 않는다.

규모가 커지면 관리자 계정 인증, 남용 방지, 접근 감사,
별도 데이터베이스를 검토해야 한다.

## 측정의 한계

IntersectionObserver로 섹션이 한 픽셀 이상 화면에 보인 구간을 센다.

문서가 숨겨진 구간은 화면 노출 시간에 포함하지 않는다.

긴 섹션의 절반 노출을 요구하지 않아 모바일의 긴 영역도 기록한다.

여러 섹션이 동시에 보이면 각각 시간이 누적된다.

따라서 섹션별 시간을 더한 값은 전체 시간보다 클 수 있다.

화면 노출은 읽기나 이해를 보장하지 않는다.

영상은 약 250ms 간격으로 재생 상태와 재생 위치를 확인한다.

일시정지, 숨겨진 문서, 비정상적으로 큰 위치 이동은 재생으로 세지 않는다.

재생 속도가 바뀌는 경계 구간도 제외한다.

되감은 뒤 다시 재생하면 재생 초에 다시 포함된다.

플레이어 밖에서 본 시간은 알 수 없다.

광고나 브라우저 정지, 매우 작은 탐색 동작 등으로 오차가 생길 수 있다.

클라이언트 기록은 위변조 방지된 감사 로그가 아니다.

사진 준비 안내는 실제 사진 열람으로 세지 않는다.

## 처음 점수의 해석

페이지 순서상 축제 소개가 처음 마음 문항보다 앞에 있다.

따라서 처음 점수를 방문 전 사전 점수로 해석하면 안 된다.

영상으로 바로 이동하면 최초 점수보다 먼저 영상을 볼 수도 있다.

이를 숨기지 않고 최초 점수 선택 시점의 탐색 기록을 함께 남긴다.

처음 점수를 수정할 수 있으므로 최초 값과 마지막 수정 시각도 남긴다.

이 자료는 콘텐츠 노출과 관심 변화의 관련성을 살피는 자료다.

축제 소개가 관심을 증가시켰다는 인과관계는 입증하지 않는다.

## 개인정보 운영 전 확인

90일은 이 구현에서 정한 제안 보관 기간이다.

법에서 일률적으로 정한 기간이라는 뜻이 아니다.

운영팀의 실제 목적과 방침에 맞게 확정해야 한다.

변경 시 src/config.js, server/apps-script.gs,
화면 안내와 문서의 기간을 함께 수정해야 한다.

기존 데이터의 expiresAt은 자동 소급 변경되지 않는다.

실제 운영 책임자, 문의 주소, Google 서비스 이용 조건,
관련 개인정보 의무와 동의 문구를 검토해야 한다.

운영 전까지 실제 참여자 이메일을 수집하지 않는 것을 권장한다.

만료 정리 트리거가 실패하지 않는지 실행 기록을 확인한다.

내려받은 CSV와 별도 복사본도 운영팀이 같은 방침으로 정리해야 한다.

동의 철회 요청은 운영자가 해당 응답과 관련 복사본을 찾아 처리한다.

자동 이메일 발송과 자동 철회 신청 화면은 포함하지 않았다.

## GitHub Pages

GitHub 저장소에 프로젝트 파일과 원본 이미지 파일을 올린다.

Settings의 Pages에서 배포 소스로 GitHub Actions를 선택한다.

Actions의 저장소 변수에 필요하면 다음을 추가한다.

- VITE_ENDPOINT
- VITE_PRIVACY_CONTACT

main 브랜치에 올리면 포함된 워크플로가 빌드와 배포를 수행한다.

vite base는 ./이다.

코드의 public 파일 경로도 BASE_URL을 통해 만든다.

클라이언트 라우터가 없고 해시 이동과 쿼리만 사용한다.

저장소 하위 경로에서도 별도 라우팅 재작성 없이 구성한다.
